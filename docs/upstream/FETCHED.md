# Upstream documentation snapshot — X API v2

Source of truth for every endpoint wrapper (ADR-0003). The files in this directory are
written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the pages in the
table below and refreshed deliberately by PR, so that changes show up as diffs. This
file is generated by the same script; nothing here is edited by hand.

## Attribution

Neither the pages nor the OpenAPI document print a copyright line. They state these
terms, recorded as printed in `ATTRIBUTION` of `scripts/refresh_upstream.py`:

- `X Developer Agreement` printed in terms/developer-agreement.md: the title of
  https://docs.x.com/developer-terms/agreement, the binding agreement that governs
  access to and use of the X API and X Content, kept whole.
- `Last Updated: April 27, 2026` printed in terms/developer-agreement.md: the date
  printed under the X Developer Agreement's title.
- `X Developer Policy` printed in terms/developer-policy.md: the title of
  https://docs.x.com/developer-terms/policy, part of the contract that governs the X API
  and X Content as its first section says, kept whole.
- `X Developer Agreement and Policy`, a link to
  https://developer.x.com/en/developer-terms/agreement-and-policy.html, printed in
  openapi/openapi.json: the name of the OpenAPI document's `info.license`, whose url
  `info.termsOfService` gives as well; developer.x.com redirects it (307) to
  https://docs.x.com/developer-terms/agreement-and-policy.html, which answered 404 when
  checked on 2026-10-29.
- `Terms of Service`, a link to https://x.com/en/tos, printed in
  https://docs.x.com/x-api/introduction: a link in the site footer of the docs.x.com
  pages, under Legal, beside Privacy Policy, Cookies and Developer Terms; the footer
  prints no copyright line.

The script stops when a page it reads states one it does not record. The documentation's
text is reproduced here as this package's reference (ADR-0003); the publisher's
objection is met by replacing it with a summary that keeps the names and semantics the
wrappers rely on.

## How this is captured

docs.x.com serves each page as Markdown when `.md` is appended to its URL, the form its
index for agents, https://docs.x.com/llms.txt, points to; the script fetches that form
and keeps it verbatim, the notice of the documentation index at its top included.
Nothing is converted, so every table is the page's own pipe table and none is kept as
HTML. The Markdown form carries no site chrome: the HTML page at
https://docs.x.com/x-api/introduction is read for its footer alone, and its text is not
kept. The OpenAPI document is the one the API serves at
https://api.x.com/2/openapi.json, kept byte for byte as fetched; its `info` names the X
Developer Agreement and Policy as its licence and terms, the two documents kept whole
under `terms/`. X serves the OAuth 2.0 scope lists of the document's `security`
requirements in a new order on each request (two fetches on 2026-10-29 differed in
nothing else). A write run writes the body as fetched, in that request's order, so a
refresh's diff shows reordered scope lists. `--check` compares the document as text with
those lists sorted and nothing else changed: where the file or the fetched body is not
exactly the document written with `json.dumps(indent=2, ensure_ascii=False)`, as X
serves it, it compares their bytes, so a difference in key order, whitespace, escapes or
numbers still counts. docs.x.com sends no ETag, and a Last-Modified that does not look
like a page's last change: on 2026-10-29 the OAuth 2.0 overview reported Last-Modified
14:20:07 UTC beside an Age of 44,585 s at 14:38 UTC. Taken, as an inference, for the
time a cache rendered the page, it can move without the page changing, and `--check`
then reports `FETCHED.md`. The API sends neither validator for the OpenAPI document.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Bytes and sha256 are those of the body as fetched, which every file here is
byte for byte; the `(no file)` row's are those of the footer text it is read for, as its
note says. Last-Modified is the HTTP header in UTC, ETag as sent, `-` where none is
sent. A page recorded without a file is `(no file)`, and a body that changes on every
request records no size, sha256 or validators. Requests go one at a time, 2 s apart,
each retried at most once, identified as `xippios-x refresh_upstream
(+https://github.com/xippios)`; no API key is sent or read.
